This chapter covers how work is saved, versioned, and backed up in Foma.

Foma automatically saves moments after the final keystroke in a unit of work. When Foma saves, it writes content directly to the user's disk using Markdown and JSON document formats to store writing, structure, and other data.

Foma also integrates with GitHub to provide robust, free, cloud-based version control for Foma projects. Please note that, while Foma never asks users to create an account or provide personal data, GitHub's services are subject to GitHub's own Terms of Service.

GitHub is a trusted software industry standard for version control and cloud backup, but if you as the writer do not wish to use Foma's GitHub integration, consider saving your projects in a cloud service of your choice like Dropbox or OneDrive. In the future, Foma will integrate with other Git hosting platforms so that users can choose their preferred platform or self-host, but for the time being, GitHub is the integration.

💬

*NOTE: Do&#x20;****NOT****&#x20;**use GitHub version control&#x20;****AND&#x20;****OneDrive/Dropbox together for the same project. You&#x20;****WILL&#x20;****suffer irretrievable data loss if you save your project to a OneDrive folder and commit/push its contents to GitHub since each service has its own way of determining the source of truth for the current project state and those determinations will fight with each other over which one wins out.*

It is highly recommended to use Foma's GitHub integration to get the absolute most out of Foma's versioning features. Foma packages Git features in writer-friendly language and usage patterns to ensure that virtually NO unit of work can ever truly be lost and no change is impossible to rewind or back out of.

Foma was designed with the Git-backed user in mind. Please review the following content to learn how to manage units of work and version control using Foma + Git.
