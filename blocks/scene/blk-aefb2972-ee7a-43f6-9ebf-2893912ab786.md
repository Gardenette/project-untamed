## Auto-Save

Foma auto-saves your work every time you stop typing. When Foma auto-saves, it writes your changes to your local hard disk. View the current save state in the bottom right corner of the screen.

While you're typing, the Auto-Save indicator will read `Typing...`

When Foma saves the current document, a checkmark and notification that reads `Auto-saved` appears.

### Save State Indicators

After you finish typing, you may notice a colored circle next to the auto-save indicator (in Nightwriter Dark Mode, this indicator is yellow). This indicates that there are some words that have been written in the current document that have been saved to the local disk, but have not been captured by a Git Snapshot or Memory.

You may also notice colored circles next to documents in the side bar.

![image-60.png](assets/image-60.png)

These circles indicate that the document has work that has been saved to the local disk, but not captured in a Git Snapshot or Memory yet.

When you collapse nested items in the side bar, if any of the nested contents have changes that have been saved locally but have not been captured in a Snapshot or Memory, the save state indicator rolls up to its parent.

## Snapshots & Memories

Snapshots capture the changes that have been made across the project since the last snapshot was taken. Snapshots describe the state of changed documents, not necessarily the state of the entire project.

To illustrate, follow these steps:

1. Type something in this scene. Notice the yellow indicator next to the scene "Version Control in Foma".

![image-67.png](assets/image-67.png)

2. Click on the `Loremaster's Memory` icon in the upper-right corner of the title bar.

![image-68.png](assets/image-68.png)

3. You will see a list of outstanding changes at the top of the `Loremaster's Memory` menu. This will include any other changes that have been made in the project since the last snapshot.

![image-69.png](assets/image-69.png)

Changes that have been made since the last time a snapshot was taken

Changes to text are interactive. To see exactly which lines changed, click on the name of the document that has been changed to expand. Additions are green. Subtractions are red.

![image-70.png](assets/image-70.png)

Images that have been added to a document are represented as Markdown

💬

*NOTE: you may see the entire contents of this interactive tutorial as outstanding changes if you haven't taken a snapshot yet. That is fine. They will become part of the first snapshot.*

### Undoing Work

You may notice that, as you hover over the name of a scene, chapter, or Worldbuilding block in the side bar, a "Discard changes" button appears next to the ones that have a yellow save state indicator.

![image-71.png](assets/image-71.png)

The "Discard changes" button only rewinds the document to the last snapshot. For example, if a document was last snapped at 100 words and you type 5 more words in the document, clicking the "Discard changes" button next to the document in the side bar will rewind the 5 words that were added since the last memory.

### Reverting Work

Reverting work is different from undoing work in that a "reverting" rewinds to the state the work was in during a previous snapshot. If you have committed 3 snapshots to memory and click "Restore to this memory" in the `Loremaster's Memory` menu, the Loremaster will rewind to the project's state when that memory was created.

### Creating Snapshots & Memories

A snapshot is an image of all of the changes that have been made in the project since the last time a snapshot was taken. A memory is a collection of snapshots rolled up together. Most of the time, this distinction does not matter, as the workflow is designed to sync a single snapshot as a memory automatically, but there are some edge cases where it may be helpful to understand the distinction.

There are several ways to create a Snapshot or Memory:

1. From the Loremaster's Memory menu

Access the `Loremaster's Memory` menu from the upper-right corner of the title bar. Click "Remember" to create a snapshot of all outstanding saved work. Then, click `Sync to Archive` to send those snapshots to your GitHub repository.

💬

*NOTE: You can also skip the "Remember" button and click "Sync to Archive" if you don't care about describing the unit of work that you're remembering. Foma will create an automatically-titled snapshot and sync it in one action.*

2. From the Archive menu

Click the Archive button in the upper-right corner of the title bar. Then, click "Sync to Archive" to automatically remember and sync your work.

3. Inside the Editor using either the `/save` or `/memory` command.

Using the `/save` command opens a popup to insert a description. After describing the unit of work, hit Enter. A memory will be created and synced to GitHub automatically.

![image-81.png](assets/image-81.png)

Type /save to expose the save memory command

![image-82.png](assets/image-82.png)

Type a meaningful message and hit "Enter" or click "Sync" to snapshot+ sync in one action

4. For Git power users, Foma also exposes a Git terminal so that you have full control of all of the power that Git has to offer. This terminal can be accessed with the `/git` command or by accessing `Settings` → `Tools` → `Git Terminal`.

![image-64.png](assets/image-64.png)

💬

*NOTE: do not use the Git Terminal directly unless you are&#x20;**extremely**&#xA0;confident in your Git skills. Foma has intentional guardrails in place to help writers use Git for a writing workflow that may be difficult to see unless you understand how the underlying structures of Foma projects relate to each other, how to resolve merge conflicts, and how to leverage branching/rebasing/reverting to restore a project to the last-known working state.*

### Automatic Sync

If you are concerned about forgetting to create and sync memories to your remote GitHub archive, Foma can automatically create memories and sync them on a timer. Auto-memory and auto-sync settings are configured in `Settings → Memory`.

Auto-memories can be configured to fire every 5, 10, 30, or 60 minutes. However, automatically creating a memory does NOT mean that your work will be synced automatically. To ensure that auto-memories are auto-synced, set your desired Auto-memory interval and toggle "Auto-sync on auto-memory" on.
